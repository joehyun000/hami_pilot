# HAMi Tail-Latency 파일럿 결과 요약

## 현재 상태

**실제 GPU 성능 결과는 아직 없다.** Mac에서 완료한 것은 하네스 구현과 synthetic dry-run 검증이다. synthetic GO 출력은 parser·paired contrast·보고서 생성이 연결됐음을 확인하는 테스트 데이터이며 연구 증거로 인용하면 안 된다.

## 서버에서 채울 결과

| 항목 | 값 |
|---|---|
| GPU / driver / CUDA | 서버 preflight 후 자동 기록 |
| probe image digest | 미측정 |
| vanilla image digest | 미측정 |
| 선택 QPS | calibration 후 결정 |
| probe overhead paired median | 미측정, 1.05 이하여야 함 |
| P0 wait | 미측정, 0이어야 함 |
| P1/P3 wait | 미측정, 0보다 커야 함 |
| 20개 complete run | 미실행 |
| 최종 결정 | 미정 |

## 서버 실행 gate

1. probe/vanilla image 두 개를 빌드한다.
2. preflight에서 Docker·CUDA·빈 GPU·입력 hash·source commit을 통과한다.
3. single-victim P0 QPS sweep에서 최대 지속 가능 QPS의 70%를 고정한다.
4. vanilla/probe P0를 3쌍 교차 실행해 overhead가 5% 이하인지 확인한다.
5. 고정 QPS의 P0/P1/P3 30초 smoke에서 P0 wait=0, P1/P3 wait>0을 확인한다.
6. 그 뒤에만 무작위 5-block P0~P3 20-run을 실행한다.

## 판정 규칙

- GO: P1/P0, P3/P1, P3/P2 중 하나 이상이 5 block 중 4개 이상 증가하고 paired p99 ratio 중앙값이 1.10 이상
- 부분 GO: wait 메커니즘과 반복 방향은 보이지만 중앙 slowdown이 10% 미만
- NO-GO: 방향 불안정, probe overhead 초과, P0 wait 발생, P1/P3 wait 미발생 또는 불완전 run

10%는 논문 통계적 유의성 기준이 아니라 CUPTI와 후속 workload에 비용을 투입할지 정하는 탐색 gate다.
