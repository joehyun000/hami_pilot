# 공개 워크로드 선정표

| 자료 | 파일럿에서의 역할 | 사용할 수 있는 것 | 대표성의 한계 | 현재 결정 |
|---|---|---|---|---|
| MLPerf Inference v5.1.1 BERT-Large SQuAD Server | 실제 CUDA 실행을 포함한 1차 인과 검증 | 공개 reference SUT, 입력 데이터, 모델, LoadGen open-loop Server 요청 | 특정 기업의 원래 서비스 trace가 아니며 공식 MLPerf 제출 설정도 아님 | **1차 파일럿에 사용** |
| BurstGPT | LLM 요청 도착·크기 분포의 외적 타당성 | 공개된 요청 패턴 범위 내 arrival/token 특성 재생 | 원래 비공개 모델·GPU·서빙 stack을 완전 재현하지 못함 | 파일럿 GO 이후 |
| Alibaba GenTD26 | 생성형 workload 조건 범위 선정 | 공개 저장소가 제공하는 QPS·작업 특성·지연/사용률 범위 | 공개 필드만으로 원래 서비스의 실행 인과를 복원할 수 없음 | 파일럿 GO 이후, 필드 재확인 후 |
| 합성 CUDA kernel | probe와 quota path sanity check | kernel 크기와 반복을 의도적으로 통제 | 실제 온라인 추론 대표성이 없음 | 메커니즘 점검에만 사용 |

## 선정 원칙

- “공개 trace가 있다”와 “원래 시스템을 재현했다”를 같은 뜻으로 쓰지 않는다.
- MLPerf는 표준 실행 workload이지만 본 실험은 공식 MLPerf submission이 아니다.
- 실제 요청 분포를 추가하더라도 실행 모델과 serving stack이 다르면 arrival/size 분포 재생이라고 표현한다.
- 1차 파일럿이 NO-GO이면 BurstGPT·GenTD26 확장 실험을 시작하지 않는다.
