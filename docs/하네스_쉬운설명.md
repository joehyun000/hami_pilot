# 파일럿 하네스 쉬운 설명

## 1. 하네스가 무엇인가

하네스는 실험을 대신 판단하는 인공지능이 아니라, **정해 둔 실험 절차를 매번 같은 방식으로 수행하고 기록하는 실험 조교**에 가깝다.

사람이 수동으로 30회를 실행하면 조건을 잘못 넣거나, 이미 끝난 실험을 다시 돌리거나, 실패한 결과를 덮어쓸 수 있다. 하네스는 이런 실수를 줄인다. 연구 질문과 판정 기준을 정하는 사람은 연구자이고, 하네스는 그 결정을 반복 가능하게 실행한다.

## 2. 전체 흐름

```text
여섯 조건 확인
    ↓
공통 요청량 선정
    ↓
짧은 조건 확인
    ↓
30회 본 실험
    ↓
같은 묶음끼리 비교
    ↓
계속·제한적 계속·중단 판단 자료 생성
```

## 3. 왜 공통 요청량을 먼저 정하는가

요청이 처리 능력보다 많이 들어오면 처리할 일이 계속 쌓인다. 그러면 응답시간에는 두 시간이 섞인다.

1. 원래 처리할 일이 쌓여서 기다린 시간
2. HAMi가 사용량을 제한하며 기다리게 한 시간

이 둘이 섞이면 HAMi 제한 방식이 원인이라고 말하기 어렵다. 그래서 제한이 있는 C2·C4·C5가 안정적으로 처리할 수 있는 양을 각각 찾는다. 가장 낮은 처리 능력을 기준으로 70%만 보내면 여유를 두면서 모든 조건의 요청량을 같게 유지할 수 있다.

예를 들어 안정 처리 능력이 다음과 같다고 하자.

| 조건 | 안정적으로 처리 가능한 초당 요청 수 |
|---|---:|
| C2 | 8 |
| C4 | 4 |
| C5 | 2 |

가장 낮은 값은 2이고, 그 70%는 1.4다. 따라서 여섯 조건 모두 초당 1.4개의 같은 요청을 받는다.

## 4. 왜 짧은 조건 확인을 하는가

설정 파일에 50%라고 적혀 있는 것과 실제로 제한이 작동하는 것은 다르다. 짧은 조건 확인은 다음을 검사한다.

- 50%인 작업에서는 HAMi 제한 대기가 실제로 기록되는가?
- 100%인 작업에서는 예상하지 않은 제한 대기가 기록되지 않는가?
- 정한 요청량의 98% 이상을 실제로 처리하는가?

마지막 검사가 실패하면 일반적인 요청 적체가 섞일 가능성이 있으므로 본 실험으로 넘어가지 않는다.

## 5. 30회는 어떻게 구성되는가

한 묶음에는 C0부터 C5까지 여섯 조건이 한 번씩 들어간다. 이 묶음을 다섯 번 반복하므로 총 30회다.

각 묶음 안의 실행 순서는 무작위로 섞는다. 장비가 시간이 지나며 조금 뜨거워지는 현상이 특정 조건에만 몰리지 않게 하기 위해서다. 하지만 무작위 순서만으로 온도 영향을 없앨 수는 없으므로 실제 장비에서는 동작 속도 고정과 시작 온도 기준도 필요하다.

## 6. 왜 같은 묶음끼리 비교하는가

첫째 날의 C2와 마지막 날의 C1을 비교하면 장비 상태나 외부 환경 차이가 섞일 수 있다. 그래서 같은 묶음 안에서 실행된 두 조건의 응답시간을 나눈다.

예를 들어 한 묶음에서 다음과 같다면:

- C1의 “전체 요청 99%가 끝나는 응답시간 경계”: 100밀리초
- C2의 같은 값: 120밀리초

C2 ÷ C1은 1.20이다. 측정 대상의 사용량을 제한했을 때 느린 요청 구간이 20% 길어졌다는 뜻이다.

이 비율을 다섯 묶음에서 각각 구한다. 다섯 개 중 네 개 이상이 같은 방향인지 보고, 다섯 비율의 가운데 값을 대표값으로 사용한다.

## 7. 결과를 어떻게 읽는가

- 비율이 1보다 크다: 위에 놓인 조건의 응답시간이 더 길다.
- 비율이 1보다 작다: 위에 놓인 조건의 응답시간이 더 짧다.
- 가운데 값이 1.10 이상이다: 약 10% 이상의 반복적인 느려짐 후보다.
- 가운데 값이 약 0.91 이하이다: 반대 방향으로 약 10% 이상의 보호 효과 후보다.

이 값만으로 원인을 확정하지 않는다. 파일럿은 “현상이 반복되며 더 깊게 볼 가치가 있는가”를 고르는 단계다.

## 8. 중단 후 다시 실행하면 어떻게 되는가

각 실험 폴더에는 계획됨, 실행 중, 완료, 실패 상태가 기록된다.

- 완료된 실험: 다시 실행하지 않는다.
- 아직 하지 않은 실험: 다음 순서부터 실행한다.
- 실패한 실험: 원본을 보존하고 자동으로 덮어쓰지 않는다.
- 연구자가 다시 시도하겠다고 명시한 실패 실험: 이전 결과를 별도 보관한 뒤 새 시도를 만든다.

GPU 대여 시간이 끊기거나 다음 날 이어서 해야 할 때 처음부터 다시 시작하지 않아도 된다.

## 9. 현재 코드가 아직 답하지 못하는 것

하네스가 로컬 자동검사를 통과한 것과 연구 현상이 확인된 것은 다르다. 아직 실제 GPU에서 다음을 확인해야 한다.

1. HAMi 50% 설정이 이 장비에서 실제 제한 대기를 만드는가?
2. 선택한 요청량에서 처리할 일이 시간에 따라 쌓이지 않는가?
3. GPU 온도와 동작 속도를 일정하게 유지할 수 있는가?
4. HAMi가 기다리게 한 시점과 유난히 느린 개별 요청을 시간상 연결할 수 있는가?

이 질문은 내일 실제 장비에서 확인한 뒤 하네스를 한 번 더 보완해야 한다.

## 10. 연구자가 스스로 확인할 네 문장

실험 전에 자료를 보지 않고 다음 네 문장을 자기 말로 설명해 본다.

1. 지금 알고 싶은 것:
2. 그것이 중요한 이유:
3. 확인하기 위해 비교할 것:
4. 결과에 따라 내릴 결정:

막히는 문장만 다시 확인한다. 네 문장을 설명하지 못하는 상태에서는 본 실험을 시작하지 않는다.
