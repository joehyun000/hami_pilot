# 연구기획서

## 1. 연구 제목

### 국문 제목 후보

**GPU 공유 환경에서 HAMi 사용량 제한이 느린 추론 요청의 응답시간에 미치는 영향**

### 영문 제목 후보

**Characterizing Slow-Request Latency under HAMi GPU Usage Control in Shared Inference Workloads**

영문 제목은 투고 단계에서 관련 문헌의 표현과 학술대회 양식에 맞춰 다시 검토한다.

## 2. 연구를 한 문장으로 설명하면

> 평균적으로는 처리 자원이 충분한 온라인 추론 환경에서도, HAMi가 작업별 GPU 사용량을 제한하는 과정이 일부 요청의 응답시간을 불안정하게 만드는지 측정한다.

## 3. 연구 배경

GPU는 비용이 크기 때문에 한 장을 여러 작업이 함께 사용해 활용률을 높이려는 요구가 있다. 그러나 여러 작업이 같은 GPU를 사용하면 다음 문제가 발생할 수 있다.

- 작업들이 GPU 연산 자원과 메모리 자원을 두고 경쟁한다.
- 일부 작업이 GPU를 과도하게 사용해 다른 작업의 실행 기회를 줄인다.
- 평균 응답시간은 안정적이어도 일부 요청만 유난히 느려질 수 있다.

HAMi는 작업별 GPU 사용량에 한도를 두어 과도한 독점을 줄이는 소프트웨어 기반 공유 방식을 제공한다. 이 제한은 공정한 공유를 돕지만, 사용 한도를 적용하는 과정에서 GPU 작업의 실행을 기다리게 할 수 있다.

코드에 실행 대기 경로가 존재한다는 사실만으로 실제 서비스 문제가 증명되지는 않는다. 평균적으로 처리 능력에 여유가 있는 상황에서도 실행 대기가 발생하는지, 그리고 그 대기가 느린 일부 요청의 응답시간과 반복적으로 연결되는지 실제 공개 추론 작업으로 확인해야 한다.

## 4. 연구 문제

현재 연구가 해결하려는 문제는 다음과 같다.

> GPU 사용 한도 안에서 전체 요청을 안정적으로 처리할 수 있는데도, HAMi의 사용량 제한이 일시적인 실행 대기를 만들어 일부 온라인 추론 요청의 응답시간을 길게 만들거나 반대로 안정화하는가?

이 질문은 다음의 당연한 현상과 구분해야 한다.

- 사용할 수 있는 GPU 자원을 줄이면 전체 처리 속도가 낮아지는 현상
- 처리 능력보다 많은 요청을 보내 요청이 쌓이는 현상
- HAMi와 무관하게 이웃 작업들이 GPU를 두고 경쟁하는 현상

## 5. 연구 목표

### 파일럿 목표

1. HAMi 사용량 제한 조건에서 실행 대기가 실제로 발생하는지 확인한다.
2. 요청 적체가 없는 상태에서 느린 일부 요청의 응답시간이 반복적으로 달라지는지 확인한다.
3. HAMi 연결 자체의 비용, 사용량 제한의 영향, 이웃 작업 경합의 영향을 조건 비교로 구분한다.
4. 후속 정밀 연구에 GPU와 시간을 투입할지 결정한다.

### 파일럿 통과 후 목표

1. HAMi 실행 대기와 개별 느린 요청의 시간 관계를 정밀하게 연결한다.
2. 요청량, GPU 사용 한도, 작업 특성에 따라 영향이 나타나는 경계를 찾는다.
3. HAMi 사용량 제한이 비용으로 작동하는 조건과 보호 장치로 작동하는 조건을 구분한다.
4. 반복 가능한 영향이 확인된 경우에만 이를 줄이거나 활용하는 설정 방법 또는 제어 방법을 설계한다.

## 6. 연구 질문

### 연구 질문 1

이웃 작업이 없는 상태에서도 HAMi의 GPU 사용량 제한이 느린 일부 추론 요청의 응답시간을 변화시키는가?

### 연구 질문 2

이웃 작업이 있는 상태에서 HAMi의 GPU 사용량 제한은 일반적인 GPU 경합과 구분되는 추가 영향을 만드는가?

### 연구 질문 3

HAMi 사용량 제한은 느린 요청을 항상 증가시키는가, 아니면 이웃의 과도한 사용을 막아 일부 조건에서 응답시간을 안정화하는가?

파일럿은 첫 번째와 두 번째 질문의 현상 존재 여부를 우선 판단한다. 세 번째 질문의 조건 범위는 파일럿 통과 후 연구한다.

## 7. 연구 가설

### 중심 가설

> 평균 요청량이 GPU 사용 한도 안에서 안정적으로 처리되는 상황에서도, HAMi의 일시적인 실행 대기는 느린 일부 요청의 응답시간에 반복 가능한 변화를 만든다.

### 이웃 작업에 관한 가설

> 이웃 작업이 있을 때 HAMi의 사용량 제한은 일반적인 GPU 경합과 상호작용해 느린 요청을 더 증가시키거나, 이웃의 독점을 막아 감소시킬 수 있다.

### 연구를 지지하지 않는 결과

- 이웃 작업 경합만 나타나고 HAMi 사용 한도의 추가 영향이 없다.
- 실행 대기는 관측되지만 느린 요청 구간의 응답시간과 반복 가능한 관계가 없다.
- 유효한 조건에서 결과 방향이 계속 달라진다.

## 8. 연구 방법 개요

### 실행 작업

- MLPerf Inference BERT-Large SQuAD Server 참조 작업
- 측정 대상과 이웃에 같은 모델·데이터·요청 형태 사용
- 공식 MLPerf 성능 제출이 아닌 연구용 공개 작업으로 사용

### 여섯 실험 조건

1. HAMi가 없는 기준 조건
2. HAMi 라이브러리만 연결한 조건
3. 이웃 없이 GPU 사용 한도만 적용한 조건
4. 사용 한도 대기 없이 동일한 이웃 작업만 추가한 조건
5. 이웃은 100%로 유지하고 측정 대상만 50%로 제한한 조건
6. 측정 대상과 이웃을 모두 50%로 제한한 조건

다섯 번째 조건은 이웃을 고정한 채 측정 대상의 사용 한도만 바꾸기 위한 중간 조건이다. 여섯 번째 조건과 비교하면 측정 대상은 고정한 채 이웃의 사용량만 제한한 보호 효과를 볼 수 있다.

### 공통 요청량

측정 대상만 제한한 조건, 이웃은 100%로 두고 측정 대상만 제한한 조건, 두 작업 모두 제한한 조건에서 요청이 쌓이지 않는 요청량을 찾는다. 동시에 HAMi의 실행 대기는 실제로 발생해야 한다. 선택한 요청량을 모든 조건에 동일하게 사용한다.

이웃 작업이 있는 조건에서는 측정 대상과 이웃에 같은 초당 요청 수를 각각 보낸다. 두 작업의 모델, 데이터와 요청 형태도 동일하게 유지한다.

평균 초당 요청 수는 고정하되 개별 요청의 도착 간격은 서버 환경처럼 불규칙하게 구성한다. 이 방식은 평균 처리 능력에는 여유가 있지만 짧은 순간 요청이 몰리는 상황에서 사용량 제한의 영향을 확인하기 위한 것이다.

### 반복

여섯 조건을 한 묶음으로 만들고 실행 순서를 무작위로 바꿔 다섯 묶음을 실행한다. 총 본 실험은 30회다. 중단 후 다시 시작할 때는 완료된 한 차례의 실험을 다시 돌리지 않고, 환경과 GPU 동작 속도 설정을 재확인한 뒤 남은 조건부터 이어서 실행한다.

상세 절차와 판정 기준은 [파일럿 실험설계안](./파일럿_실험설계안.md)을 따른다.

## 9. 측정 내용

### 서비스에서 관찰되는 결과

- 요청별 응답시간
- 전체 요청의 99%가 이 시간 안에 끝나는 응답시간 경계: 파일럿 계속 여부를 정하는 중심 판정값
- 가장 느린 1% 요청들의 응답시간: 원인 해석을 돕는 참고값
- 완료 요청량과 초당 처리량
- 미리 정한 응답시간 목표를 넘긴 요청 비율

### 원인 판단을 돕는 내부 기록

- HAMi가 실제로 실행을 기다리게 한 횟수
- 실행 대기의 누적 시간
- GPU 사용률, 메모리 사용량, 온도와 동작 속도
- 요청 적체 여부와 시간에 따른 응답시간 변화

장비와 권한이 지원하면 GPU 동작 속도를 고정한다. 지원되지 않으면 사전에 정한 온도 기준과 열로 인한 동작 속도 저하 여부를 확인해 조건 간 환경 차이를 줄인다.

## 10. 파일럿 판정

### 연구 계속

다음 조건을 모두 만족한다.

- 요청이 쌓이지 않는다.
- HAMi 사용 한도 조건에서 실제 실행 대기가 발생한다.
- 측정 대상 제한 비교 또는 이웃 제한의 보호 효과 비교에서 다섯 묶음 중 네 묶음 이상 같은 방향의 응답시간 변화가 나타난다.
- 묶음별 99% 완료 경계 비율 다섯 개의 중앙값이 1.10 이상이거나 그 역수인 약 0.909 이하이다.

1.10과 그 역수 기준은 논문에서 통계적 유의성을 주장하기 위한 기준이 아니다. 후속 정밀 측정에 자원을 투입할지를 정하기 위한 탐색 기준이다.

### 제한적으로 계속

변화 방향은 네 묶음 이상에서 반복되지만 비율의 중앙값이 0.909보다 크고 1.10보다 작으면 요청량 또는 사용 한도 경계를 한 번만 추가 확인한다.

### 현재 방향 중단

- 일반적인 이웃 작업 경합만 확인된다.
- 측정 대상의 사용 한도와 이웃의 사용 한도에서 추가 영향이 반복되지 않는다.
- 유효한 실험 조건을 만들었는데도 실행 대기와 느린 요청의 관계가 나타나지 않는다.

### 판정 보류

요청 적체, 측정 장치의 큰 영향, 실행 대기 조건 실패 또는 GPU 환경 변화가 있으면 가설을 판단하지 않고 실험을 수정한다.

## 11. 예상되는 연구 기여

파일럿이 통과한 경우에만 다음 기여를 목표로 한다.

1. HAMi 연결 비용, 사용량 제한에 따른 실행 대기, 일반적인 이웃 작업 경합을 분리하는 비교 방법
2. 공개 추론 작업에서 사용량 제한이 느린 요청 구간에 미치는 영향의 실측 결과
3. 사용량 제한이 비용 또는 보호 장치로 작동하는 조건에 관한 실험적 근거
4. HAMi 기반 GPU 공유 환경을 설정할 때 느린 요청을 줄이기 위한 측정 기반 지침

이 항목들이 기존 연구에 없는 새로운 학술 기여인지는 관련 문헌을 다시 조사한 뒤 확정한다. 파일럿 결과만으로 독창성을 주장하지 않는다.

## 12. 연구 범위

### 이번 파일럿에 포함

- 단일 물리 GPU
- 단일 BERT 작업
- 동일한 BERT 이웃 작업
- GPU 사용 한도 한 값
- 공통 요청량 한 값
- 여섯 조건과 다섯 번의 묶음 반복

### 이번 파일럿에서 제외

- 여러 모델과 공개 요청 기록 전체 비교
- 여러 GPU 세대 비교
- 여러 사용 한도 값 전체 탐색
- CUPTI 기반 GPU 작업 단위 원인 분해
- 다른 GPU 공유 시스템과의 성능 우열 비교
- 자동 배치 또는 전환 정책 구현
- 기업 도입률이나 실제 사용자 불편의 직접 측정

## 13. 연구 진행 단계

### 1단계: 현상 존재 확인

이번 6조건 파일럿으로 실행 대기와 느린 요청 구간의 반복 가능한 관계를 확인한다.

### 2단계: 원인과 경계 확인

파일럿이 통과하면 요청 단위 시간 연결 계측을 추가하고, 요청량과 GPU 사용 한도를 제한적으로 넓힌다.

### 3단계: 외부 조건 확인

동일한 현상이 다른 공개 추론 작업이나 다른 GPU에서도 나타나는지 확인한다.

### 4단계: 해결 방법 검토

반복 가능한 문제 구조가 확인된 경우에만 사용 한도 설정 지침이나 대기 완화 방법을 설계한다. 파일럿 직후 바로 정책 구현으로 넘어가지 않는다.

| 느린 요청과 실행 대기의 시간 관계가 불명확 | 누적값만으로 완전한 원인을 주장 | 파일럿 통과 후 요청 단위 시간 계측 추가 |

## 15. 다른 사람에게 설명하는 짧은 말

> GPU를 여러 작업이 같이 사용하면 한 작업이 자원을 과도하게 사용하는 것을 막기 위해 사용량 제한이 필요합니다. HAMi는 이 제한을 적용하는 과정에서 GPU 작업을 잠시 기다리게 할 수 있습니다. 저희는 전체 요청을 처리할 자원은 충분한데도 이 실행 대기 때문에 일부 추론 요청만 유난히 느려지는지 확인하려고 합니다. HAMi 연결 자체의 비용, 측정 대상의 사용량 제한, 이웃 작업과의 일반적인 경합, 이웃 사용량 제한의 보호 효과를 하나씩 구분하기 위해 여섯 조건을 같은 요청량으로 반복 비교합니다. 현상이 반복되고 크기도 충분할 때만 정밀한 원인 분석으로 연구를 확장합니다.

## 16. 현재 연구에서 지켜야 할 표현

### 파일럿 전 사용할 수 있는 표현

- HAMi의 사용량 제한 과정에 실행 대기가 존재하며, 이것이 느린 일부 추론 요청에 영향을 주는지 확인한다.
- 사용량 제한은 비용과 보호 효과를 모두 만들 가능성이 있다.
- 파일럿은 현상의 존재와 측정 가능성을 판단한다.

### 파일럿 전 사용하면 안 되는 표현

- HAMi는 느린 요청을 반드시 증가시킨다.
- HAMi 때문에 실제 사용자가 불편을 겪는다.
- 모든 GPU 공유 방식이 같은 문제를 가진다.
- GPU 사용량을 절반으로 제한했더니 느려졌으므로 HAMi에 문제가 있다.
- 한 종류의 GPU와 BERT 결과를 모든 모델과 GPU에 일반화할 수 있다.
